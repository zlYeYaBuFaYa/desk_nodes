## Implementation and defaults

`Sources/DeskNodesActions/EdgeReveal.swift` contains production portable topology, side resolution and timing. Coordinates are bottom-left AppKit points, with negative origins supported. Triggering uses **full NSScreen.frame**, not the menu-bar/Dock-reduced visibleFrame used for ordinary docking. Each selected left/right edge uses a 2pt inward strip and strictly the middle 60% of that display's full height (20%/80% endpoints excluded). Another display occupying the immediately exterior side blocks that y-coordinate, including touching endpoints, partial seams, overlaps and mirrored/duplicate frames. A real gap leaves an exterior edge. Middle-60% clipping happens before seam exclusion; blocked segments do not widen/recenter the trigger elsewhere.

`RevealTiming` requires the same screen/side candidate continuously sampled for **0.25s**, then requires **0.4s** outside both panel and its original trigger before closing. Comparisons use deadline addition to avoid subtraction rounding at exact thresholds. Reentry resets exit timing. Vertical direction is never used: moving down anywhere inside the complete panel cannot dismiss it. Marked composition and attached sheets hold it open. A different screen cannot teleport an already-open panel; close and dwell again. Nonfinite/reversed time resets pending deadlines, preserving an already visible panel conservatively. Production supplies monotonic system uptime. Polling observes positions, not the path between samples, and run-loop scheduling adds latency; exact thresholds are policy, not a hard realtime guarantee.

`Sources/DeskNodesApp/EdgeRevealController.swift` retains one dedicated `RevealPanel`, outer vertical NSScrollView, and one existing `NoteCardView` presentation per live note ID. Every live note is included in the store's stable order, including ordinary collapsed/overflow notes; reveal presents their full contents without changing durable collapse/placement. Cards grow with their contents inside the outer scroll, without the ordinary 480pt height cap. There is no six-note limit, copied SQLite dataset, mock list, hidden-note model or occlusion detection. Geometry intent follows prototype02: 272pt panel, 8pt side/12pt vertical inset, 16pt container corners, solid `F2F0EB` light / `242321` dark container, 16pt horizontal container padding and 12pt card spacing. Existing card palette/type/controls are reused. Tiny displays fit the panel; severe clipping remains a native usability gate.

A common-mode timer polls every **25ms**, tolerance 5ms. It reads only `NSEvent.mouseLocation`; there is no global event monitor, event tap, keyboard stream, private CGS call, Accessibility API or Input Monitoring request. Settings and Dock orientation are read at most once per second. There is no performance measurement claim; timer scheduling, inactive-app delivery, power cost and secure/system sessions require Mac observation. On a store error polling stops and the existing error UI reports failure instead of silently closing/losing text.

`Settings.edgePreference` is typed `automatic/left/right`, default automatic. Native schema **6** transactionally adds the checked `settings.edge_preference` column to schema5; previous native migrations remain ordered. `Store.settings/update` round-trip it. N9 can supply controls using this existing foundation; N7 deliberately adds no Settings UI. Automatic reads only `UserDefaults(suiteName: "com.apple.dock")?.string(forKey: "orientation")`: right Dock → left reveal; bottom/left → right. This is a public preferences API, but **the Dock domain/key is not a guaranteed public Dock-position contract**. Missing, unreadable or unknown values conservatively mean right reveal. No shell `defaults` write, Dock process restart, credential access or sensitive preference enumeration. Manual preference wins regardless of Dock and survives reopen. Native preference visibility/live-refresh behavior is untested.

## Spaces, pointer and focus assumptions

Only `RevealPanel` sets `[.canJoinAllSpaces, .fullScreenAuxiliary]`. It is a borderless **nonactivating** NSPanel at public `.floating` level, key-capable, not main, and does not hide on app deactivation. Hover calls `orderFrontRegardless`, never `activate` or `makeKeyAndOrderFront`. Clicking a native editor may make it key while the fullscreen application remains active. Dismissal flushes committed owning-editor text, relinquishes first responder and orders out, without activating another application or an ordinary note. A hover-open must not steal typing; a dismissed panel must not keep receiving typing. These are explicit **acceptance assumptions**, not Linux-proven behavior.

Ordinary notes, docking rails/placeholders, empty-note flow and deletion toast keep `.fullScreenNone`; no ordinary window gains auxiliary behavior. Fullscreen deletion recovery has an inline reveal button using the same five-second slot, because the ordinary bottom toast must stay out of other apps' fullscreen. The shared Command–Z route remains available in reveal. No all-topmost mode changes the dedicated reveal policy.

Apple's [mouseLocation](https://developer.apple.com/documentation/appkit/nsevent/mouselocation) is the public current screen-coordinate position API. Its documentation is not a promise that every OS/security/session configuration exposes useful global pointer positions without authorization. Apple's [event monitoring guide](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html) states that global key monitoring has an accessibility trust restriction; this implementation avoids that mechanism entirely. Apple's [fullScreenAuxiliary](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/fullscreenauxiliary), [nonactivatingPanel](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/nonactivatingpanel) and [fullscreen guide](https://developer.apple.com/library/archive/documentation/General/Conceptual/MOSXAppProgrammingGuide/FullScreenApp/FullScreenApp.html) establish the public mechanisms, **not proof that our accessory panel can interact over every other application's fullscreen Space**. No material permission conflict was established by this documentation review; permission-free global visibility, fullscreen interaction, Spaces/Stage Manager and focus remain unexecuted. If actual macOS requires a new permission or fails this behavior, report the constraint; do not add taps, protected monitors, private Space APIs or silent permission prompts as a workaround.

Opening/closing uses 0.30s native Core Animation translation spring plus fade. Reduce Motion skips motion and close delay. A generation token prevents an old delayed close from ordering out a newly reopened panel. Display topology changes invalidate the open placement and require another dwell; a pending topology change is retained through composition, closing only after commit/cancel. An unplugged composing panel may remain geometrically offscreen until composition ends: preserving input takes precedence over forcing a cancellation. Native clipping, transition interruption and monitor recovery need physical verification.

## Shared editing, rollover and undo

Both surfaces use the **same NoteActions instance, Store, note/item IDs and deletion slot**. Actions re-read the latest store rows, so completion/title/item changes never write an old whole-note copy. `EditorSynchronization.swift` centralizes receive/flush policy: passive text can receive committed changes, but unnotified local edits can flush only from the owning key-window first responder, and never while marked. Checking only `window.firstResponder` is insufficient: a nonkey ordinary window may retain that responder while reveal edits the same item. Reconciliation explicitly checks `isKeyWindow` as well.

Active editor instances, text storage, selection, marked range and undo manager are retained during refresh, check, layout and reorder. Composing interim text is not published to the other presentation. Committed change notifications save through existing actions and refresh both surfaces. Only inactive, unmarked differing strings reconcile from the store; their old text undo history is cleared so it cannot replay a stale replacement over newer shared content. Each NoteTextView now owns a native UndoManager. Each title field owns its own field editor/undo through the public NSWindow delegate method, preventing undo from a previous title/note from transferring through a shared field editor. This intentionally makes text undo local to the editor that authored it; deletion undo remains global/latest-only. Active editor undo is not cleared by a peer's ordinary refresh. Native registration/coalescing and custom title field-editor integration are high-risk Mac gates.

AppDelegate's N6 gate now checks **ordinary AND reveal title/item composition** before any flush. All owning committed edits flush inside the existing single rollover transaction before snapshot/archive/checkpoint advance; passive copies cannot overwrite them. A false gate defers the whole operation. The existing 30s scheduler and text-change retry remain. Ordinary/reveal focus loss flushes committed ownership before resigning key; auto-dismiss refuses to close marked composition, then flushes before hiding. It never forces IME commit or cancellation to satisfy the exit timer. End-editing notifications schedule reconciliation after AppKit finishes focus transitions, preventing recursive row removal, and never write stale inactive text.

Structural card actions and deletion undo are suppressed while any surface has marked composition, preventing deletion/collapse/reorder from destroying that input. No deferred destructive action is replayed later. Note removal relinquishes only that card's responder and clears its editors' undo; archived/deleted rows clear their local undo before removal. Command–Z restores the shared latest deletion only when eligible and preferred; subsequent committed typing gives native text undo precedence, while the reveal button/ordinary toast can still restore before expiry. Exactly five seconds expires; no separate reveal expiry clock or deletion-undo stack exists. Same-note drag ownership rules remain conservative; cross-note/external transfers are rejected. No history edits or N8 features were added.
