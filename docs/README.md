## 维护约定

1. 先查代码，再更新所属章节。以 `Sources/`、`Package.swift`、资源与构建脚本确认实现，`Tests/` 说明自动覆盖，真实运行结果确认系统行为。
2. 一个规则只写在一个位置。其他文档引用该章节；功能变更更新功能文档，视觉数值更新 UI 文档，协议与机制更新技术文档。
3. 入口、索引和验收项可以提及功能名称，但不复制整段规则、默认值或实现方案。跨文档引用使用相对链接和稳定锚点。
4. 提案不能写成已实现；原型不复制完整需求文本，不提供旧版／新版两套规则。发现实现与提案有差异时记录代码的实际边界。
5. 验证记录写清执行范围。源码存在、静态检查通过、Swift 测试通过、原生人工验收通过分别记录，不相互替代。
