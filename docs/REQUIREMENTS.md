# DeskNodes 需求文档（当前实现基线）

日期：2026-11-12；基线与资料优先级见 [文档总览](README.md)。

## 1. 产品目标与使用场景

DeskNodes 是中文 macOS 原生桌面待办便签。用户通过菜单栏或常驻工具条随手记录，将清单自由放在桌面，用完成状态管理一天的工作；跨天后，已完成内容进入只读历史，未完成内容继续保留。

核心场景包括：桌面快速录入、在其他应用前台时新建、自由布局与一键整理、暂时收起整组便签、全屏应用中访问清单、回顾历史与找回误删内容、导出和恢复本机数据。

产品只面向 macOS 14+，当前用于个人本地运行；中文界面、菜单栏常驻、无 Dock 图标，无账号和云端服务。界面采用低饱和纯色与原生文字输入，优先保证中文输入、可读性和窗口行为稳定。

## 2. 概念与状态边界

- **便签**：长期存在的清单容器；身份不因跨天、移动、恢复而改变。
- **事项**：属于一张便签的文本条目，可完成、划掉、排序、删除；不能跨便签拖动。
- **划掉**：事项“不做了”，仍留在便签里并加删除线；与完成互斥，不计入进度。
- **业务日**：以当前时区及用户设置的跨天时间划分，默认 04:00。
- **历史快照**：业务日结束时冻结的便签和事项记录，只读，包含完成、删除和顺延信息。
- **单张折叠**：一张便签压成 32pt 标题条，其他便签不受影响。
- **全局收起**：桌面便签窗口汇聚并隐藏，保留其布局和单张折叠状态。
- **浮起**：临时把真实便签全部提到最前（含全屏应用），离开即放回；不复制、不移动、不持久化。
- **工具条收缩**：吸边后的胶囊变成圆形操作入口；不会改变便签的全局收起状态。
- **单张层级与浮起**：每张便签保存自己的层级（常驻最前用单张“置顶”）；浮起只临时覆盖展示效果，没有全局置顶开关。

## 3. 功能需求

### FR-01 应用启动、空状态与菜单栏

1. 启动读取本机 SQLite，迁移已支持的原生 schema，恢复展示偏好并检查跨天。
2. 不自动创建示例便签。没有便签时仍显示可拖动工具条，“新建”“设置”可用；浮起、整理和收起不可用。
3. 菜单栏包含：新建便签、显示工具条、浮起便签／放回便签、停靠子菜单、历史记录、最近删除、设置、退出。
4. 关闭设置或历史不退出应用；退出从菜单或设置页底部“退出 DeskNodes”明确触发。首次启动单独询问是否登录启动。
5. “显示工具条”恢复到已连接显示器上的展开工具条，不改变便签收起状态。

### FR-02 新建便签与自动配色

1. 工具条、菜单栏和全局快捷键进入同一新建流程。App 内还提供 ⌘N；全局默认 ⌃⌥N。
2. 新建真实自由便签，默认桌面层、无标题、自动高度、包含一个空事项。
3. 正常 UI 新建宽度取设置值（240／288／340／400，默认 288pt），高度为“随内容”或固定 200／300／400pt（固定高度关闭自动高度）；优先放在工具条所在屏幕的可用区域，避让工具条完整展开外框和已有可见便签；空间不足时采用级联位置，不承诺任意数量均无重叠。
4. 创建后选中该便签、激活应用并聚焦首个事项，允许立即输入中文。
5. 如果整组便签已收起，先展开已有便签，再创建新便签；不额外强制展开圆形工具条。
6. 七色色板按宣纸、柠黄、杏、樱、薰衣草、雾蓝、薄荷排列。统计未删除便签的颜色使用量，优先最少使用的颜色；并列时从最近创建便签的颜色之后循环选取。
7. 当前实现用于打破并列的“最近创建”候选包含保留的已删除便签；颜色数量统计只包含未删除便签。这是源码实际细节。

### FR-03 标题、事项与输入

1. 标题可省略，编辑区低强调占位为“标题”。折叠标题优先使用标题，否则使用第一条事项文字。
2. 事项支持新增、编辑、完成／取消完成、划掉／取消划掉、删除和同便签排序。完成后文字变为低强调色；划掉后文字更淡并加删除线、圆圈变淡。完成与划掉互斥，切换其一自动取消另一个。
3. 计数“完成数／总数”的总数不含划掉事项。行尾悬停操作为划掉、删除（各 22pt 点击区）和排序手柄；⌘⇧X 切换当前聚焦事项的划掉状态。
4. 回车在当前事项后新增并聚焦下一条；中文组词中的回车只处理输入法确认。空字符串事项上的退格删除该空行。
5. 在多行事项首／末视觉行使用上／下箭头，可进入相邻事项；⌘Return 切换当前聚焦事项完成状态。
6. 多行粘贴拆成事项，过滤空行，移除常见列表前缀。复选框前缀只移除文字标记，不自动设置完成状态，不等于支持 Markdown。
7. 输入暂停约 0.4 秒后保存；失焦、导出、跨天、退出等需要安全提交的边界执行明确刷新。输入法 marked text 不作为已完成编辑写回。
8. 活跃或组词中的编辑器不能因普通刷新被整体覆盖。原生选区、光标、文字撤销保持有效。
9. 失焦后清理多余空白事项，始终尽量保留一行用于输入。空白行清理不产生删除提示或历史删除成员。

### FR-04 选择、删除、撤销与最近删除

1. 点击桌面便签选中它；选择不等于键盘焦点。
2. 工具条不提供删除。删除整张便签使用该便签“更多”菜单中的“删除便签”。
3. 事项行尾提供删除事项入口。普通删除不弹确认，先安全提交可提交编辑；组词期间阻止会破坏输入上下文的结构操作。
4. 删除采用软删除，冻结最终文本，提示撤销；有效时间严格为删除后 `0 ≤ elapsed < 5` 秒。多次删除按最新有效记录优先撤销。
5. ⌘Z 优先处理最近的删除；开始新的文字输入后恢复为原生文字撤销。五秒撤销队列只在内存，不跨重启或导入。
6. 最近删除展示删除时间在最近 30×86400 秒范围内的便签和非空事项。列表随打开、重新聚焦或恢复刷新，不是实时永久清理器。
7. 恢复便签同时恢复与其同一时刻删除的未归档事项；更早单独删除的事项不自动恢复。恢复事项回到仍存在的原便签末尾。
8. 已归档完成事项不能通过最近删除再次激活；恢复不会修改封存历史。超过 30 天移出列表不表示从数据库和备份物理抹除。
9. 删除最后一张后仍保留工具条；恢复整张便签时会展开桌面并校正离线显示器位置。

### FR-05 自由布局、尺寸与兼容停靠

1. 自由便签从标题非编辑区域拖动；正文承担输入。拖动跟手，释放后保存位置和显示器。
2. 自由便签尺寸范围通常为 200×120 至 400×600pt；自动高度上限 480pt，长内容内部滚动。小屏可见区域裁限可能进一步缩小展示尺寸。
3. 手动改尺寸后关闭自动高度，可通过菜单“随内容调整高度”恢复。
4. 原有顶部、左侧、右侧停靠继续可用，靠便签菜单显式进入；自由便签拖近边缘仍保持自由。
5. 旧停靠条支持顺序、拖出与溢出标签／分页；顶部卡片宽 220pt、高 260pt，屏高不足 700pt 时使用 200pt；侧边宽 240pt。
6. 所有布局使用 macOS 逻辑 pt 与系统可用区域，避开菜单栏、Dock。显示器丢失时回退到主显示器并校正。

### FR-06 一键整理与分页

1. 用户主动整理时，按各便签所属显示器分别规划，以持久化顺序从左向右、由上向下排布。
2. 默认宽 288pt、间距 18pt、屏幕内边距 22pt；每排顶部对齐，下一排避开该排最高卡片。
3. 避让工具条完整展开目标外框，即使工具条当前为圆形仍保留占位。工具条移动不自动重排用户手动放置的便签。
4. 超出容量时分页，工具条仅在必要时显示页码与翻页入口；多屏共用当前页索引，页数较少的屏幕停留其最后一页。
5. 整理将参与的停靠便签转为自由便签并保存布局，不改标题、颜色、事项、层级或历史。反复整理在同样输入下应得到同样布局。
6. 全局收起时整理先建立新布局并展开。整理完成后仍可自由移动，不持续吸回网格。

### FR-07 全局收起与单张折叠

1. 工具条第四按钮在“收起／展开”间切换，汇聚动画约 0.28 秒；完成后真实窗口隐藏，不留下透明拦截区域。
2. 收起前提交编辑，恢复时按便签身份还原位置、尺寸、单张折叠与各自层级；展开不触发整理。
3. 胶囊旁显示最多三层颜色与数量的叠放提示，点击可展开；圆形工具条隐藏叠放提示，改在入口旁显示数量角标，超过 99 为“99+”。
4. 单张折叠单独保存，呈现 32pt 标题条，不改变全局状态。
5. 快速连续操作以最后目标为准，旧动画完成回调不能覆盖新状态。数据刷新和跨天不应意外展开已收起的窗口。
6. 全局收起目标记入本机偏好，重启后恢复；没有便签时清除空的收起状态。

### FR-08 工具条外形、磁吸与闲置收缩

1. 五动作顺序固定：新建、浮起／放回、整理、收起／展开、设置。竖向手柄在顶部，横向在左端，数量和分页在末端。
2. 默认竖向、自由放置。胶囊短边 64pt、半径 32pt，圆形入口直径 48pt。小屏长轴可滚动，手柄保留。
3. 拖动释放距外侧屏幕边缘不超过 81pt 可磁吸，最终间距 8pt。相接显示器的内部边不吸附；磁吸不改变排列方向。
4. 设置“吸边后自动收缩”为关闭／10／15／30 秒，默认 15 秒；自由摆放不自动收缩。
5. 仅稳定展开、已吸边、无操作阻断且指针离开时开始完整等待。拖动、按住、过渡、设置可见或 VoiceOver 启用时暂停。
6. 圆形悬停 140ms 或单击可展开。只悬停展开、没有点击或滚动就移出时，约 1.5 秒后收回；其他情况下使用完整闲置时长。
7. 圆形手势位移达到 4pt 视作拖动，不能穿透给随后出现的功能按钮。外部拖放经过圆形入口时，不在按住鼠标期间唤起。
8. 收缩中移入可连续恢复；展开中移出先完成展开。磁吸约 200ms，完整形态切换约 260ms。
9. 保存方向、自动收缩选项、位置、显示器、吸附边和归一化锚点，不保存动画进度；启动显示完整工具条，唤醒重新计时。

### FR-09 窗口层级与全屏访问

1. 便签保存桌面、普通、置顶三层。桌面层位于桌面图标之上、普通应用之下，编辑时可临时提升到普通层；应用失去活动状态后恢复。
2. 不提供全局置顶开关：需要常驻最前的便签使用便签菜单的单张“置顶”；临时查看全部使用浮起。
3. 实际层级为置顶的便签／停靠标签允许全屏辅助行为；工具条、叠放提示始终保持全屏可访问。设置、历史不采用该行为。该层级不承诺覆盖所有系统级窗口。
4. 旧版本保存的全局置顶偏好在升级后首次启动时清除，并以非激活提示说明一次；不自动把各便签改为单张置顶。
5. “浮起”由工具条按钮、菜单栏和全局快捷键（默认 ⌃⌥F，可改或清除）触发：全部真实便签临时成为有效置顶（含全屏应用），原地前置并激活应用；不改每张便签保存的层级，不写偏好，重启后不保持。
6. 放回：再次触发、在便签内按 Esc（组词中不响应）、切换到其他应用或全局收起；没有便签时浮起不可用并自动结束。
7. 不使用全局事件监听或辅助功能权限；若系统拒绝激活，Esc 不可用，仍可用按钮或快捷键放回。原边缘唤出面板已移除；数据库与备份中保留的边缘偏好字段不再使用。

### FR-10 跨天、归档与顺延

1. 默认 04:00，可设 00:00–23:59；使用当前时区和 Gregorian 日期，正确处理夏令时不存在或重复的时间。
2. 启动、约每 30 秒、唤醒、系统时钟／时区变化以及部分设置修改时检查，不保证在秒级精确触发。
3. 初次建立业务日检查点不伪造昨日历史。向前跨越时封存上一个已观察业务日，将未完成事项标为顺延到当前日，完成和划掉的事项进入归档并退出 live 清单（划掉不顺延）。
4. 休眠或长期未开应用跳过多日，只关闭最后观察到的一天，不给中间日期制造快照。
5. 每天最多一份封存快照；已封存内容不可更新、删除或补插成员。时钟回拨不反向归档或覆盖历史。
6. 组词时延迟，完成输入后重试；安全提交、快照、完成项归档、删除成员清理与检查点推进保持事务一致。
7. 每次成功推进后自动写 SQLite 完整副本，保留最新 7 份；失败记录日志，不回滚已完成的跨天。

### FR-11 历史记录

1. 历史窗口提供“日历／最近删除”切换。日历周一开始，可前后翻月，日期格显示当日冻结完成率细线。
2. 左侧月历及本月完成率，右侧选中日期、完成数及各便签冻结事项；支持删除标记和顺延目标提示。
3. 月完成率为所有快照的完成事项次数之和 ÷ 事项出现次数之和，包含删除记录、不含划掉事项（划掉在历史中以删除线显示）；同一未完成事项跨多天出现会重复计入，不是唯一任务去重率或日百分比平均。
4. 无分母显示“—”；当天没有快照时显示“当天没有历史记录”，不即时生成历史，也不展示实时清单冒充快照。
5. 日历内容只读；最近删除中的恢复是修改 live 数据的独立操作。

### FR-12 设置、快捷键与登录启动

1. 设置按“通用、停靠条、工具条、新建便签、快捷键、数据”分组，通常修改后立即保存，不设总保存按钮；底部提供“退出 DeskNodes”（⌘Q）。
2. 新建便签与浮起便签两个快捷键支持 Control／Option／Shift／Command 加物理 ANSI 字母、数字或 Space，至少含 Control 或 Command。
3. 拒绝系统保留组合：⌥⌘H、⌥⌘D、⌃⌥Space；两个快捷键不能相同。浮起快捷键可清除。录制 Esc 取消，冲突保留旧快捷键与数据。旧数据的新建快捷键若恰为 ⌃⌥F，浮起快捷键迁移为未设置。
4. 首次登录启动询问提供“暂不启用／启用”；拒绝后不重复问。只有首次明确同意或设置主动操作才调用 SMAppService 注册／注销。
5. 系统状态为准，能说明已启用、待批准、未注册、找不到服务等状态；导入的登录意愿不会自动注册系统服务。

### FR-13 备份、导入与本地数据

1. 数据在 `~/Library/Application Support/local.desknodes.native/DeskNodes.sqlite3`，仅本机保存，无加密功能声明。
2. 设置中导出完整原生 JSON；格式 `local.desknodes.native.backup`、version 1、schema 8；仍可导入 schema 7 备份（缺少的划掉字段按未划掉、浮起快捷键按默认）。与旧 Tauri 备份不兼容，无自动迁移。
3. 备份含 live／删除／归档数据、历史、业务设置、快捷键与登录意愿、跨天检查点、待记录删除成员，以及每张便签的布局。
4. 工具条位置／方向／收缩选项、新建便签尺寸、全局收起、整理分页属于 UserDefaults，不进入 JSON；系统登录项、临时撤销、焦点和动画也不进入。
5. 导入先解析、完整校验并创建隔离 staging 数据库，再确认替换全部本机业务数据。用户取消、格式无效、组词中或快捷键冲突时保留原数据。
6. 成功导入替换全部业务库并重建编辑上下文，清除旧撤销；保留当前本机展示偏好，不立刻补跨天。后续正常调度可推进导入的旧检查点。

## 4. 质量与非功能要求

- 原生 AppKit 常驻窗口、NSTextView 输入，低频设置和历史使用 SwiftUI；系统 SQLite，无第三方运行时依赖。
- 普通工具条动作不获取键盘焦点；新建、编辑和主动打开设置／历史按预期激活。
- 深浅色跟随系统；支持系统减少动态效果及关键控件的辅助功能名称、状态和操作。
- 数据结构使用稳定 UUID；排序、归档、恢复、导入必须维护引用完整性，不能重用删除身份。
- 数据操作出错应保留可恢复状态；后台错误用非激活提示与日志，一次性明确请求的严重错误可用模态框。
- 不承诺强制内存、CPU 或动画帧率指标；没有性能测量就不能填写达标值。
