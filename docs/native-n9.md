## Settings and lifecycle

`SettingsWindow.swift` replaces the placeholder with a retained, lazily created SwiftUI presentation/window through `AuxiliaryWindows`. Launch constructs no Settings view tree/model. It uses the existing `NoteActions` and **same Store connection** as ordinary/reveal editors and History. Closing auxiliary windows does not terminate the accessory/menu-bar application. Settings stays normal-level and excluded from fullscreen; only the existing reveal panel has fullscreen auxiliary behavior.

Prototype05's five Chinese groups are implemented: 通用 / 停靠条 / 边缘唤出 / 快捷键 / 数据. Native titlebar, 760pt content width, 40pt horizontal/20pt vertical padding, 16pt group spacing, 10pt grouped corners, 40pt minimum rows and 13pt system font express the prototype hierarchy. The content scrolls to keep explanations/errors reachable. System semantic colors support both appearances. Additional real status, error and approval explanations increase height; there is no HTML/WebView. Native screenshot fidelity is **UNVERIFIED**.

Rollover defaults to **04:00**. Hour **0–23** and minute **0–59** pickers expose the complete existing native range, including previously saved nonzero minutes; selecting/reopening never silently rounds them. The scheduler still reads settings on every attempt and uses N6's DST/clock-reversal/missed-day rules. Preference changes refresh live presentation and attempt catch-up, respecting the all-surface marked-composition gate. No system clock/timezone is changed.

Dock side top/left/right and primary/named-display choices reuse N5's transactional `dockPreference`: existing docked notes move together, keeping stable order and individual state; free notes stay free. Persistent IDs come from the existing public ColorSync UUID mapping. Missing preferred display stays saved, with a primary fallback label; ambiguous/session-only displays are omitted from durable choices. Selecting primary stores nil. Topology changes refresh choices. Settings reloads on open, activation and display changes, using explicit Binding setters rather than `onChange` writes; reading imported settings cannot accidentally redock notes or reset minutes.

Edge automatic/left/right reuses schema6 policy. Current read-only Dock orientation explains the resolved side: bottom/left → right, right → left. Missing/unrecognized/unavailable orientation explicitly explains automatic right fallback; manual side still wins. The public UserDefaults API does **not** make `com.apple.dock/orientation` a guaranteed Dock-position contract. Explanation refreshes on Settings open/activation/selection; reveal retains its existing once-per-second environment read. No preferences are written outside the app database.

## Shortcut and first-launch consent

`SystemServices.swift` uses public Carbon `InstallEventHandler`, `RegisterEventHotKey`, `GetEventParameter`, `UnregisterEventHotKey` and `RemoveEventHandler`. The single shortcut defaults to **Control+Option+N**. Settings has a text configuration field and Apply/Return action (for example `Command+Shift+7`), with visible validation/registration errors. The portable parser accepts case-insensitive Control/Option/Shift/Command names, trimmed whitespace, one physical ANSI A–Z / 0–9 / Space key, and requires Control or Command. Duplicate/unknown modifiers, unsupported keys and the three specified system combinations **Option+Command+H**, **Control+Option+Space**, **Option+Command+D** are rejected. Canonical modifier order is Control, Option, Shift, Command. Physical ANSI codes do not promise character remapping for every keyboard layout; check the actual selected layout on Mac.

`HotkeyBinding` registers a candidate **before** retiring the prior handle. A Carbon conflict leaves the old registration and stored preference intact. A persistence/import failure unregisters only the candidate. Successful persistence switches the binding and unregisters the old handle; unchanged binding persists without duplicate registration. Event IDs suppress candidates/retired events; only the current ID invokes the normal new-note action. New-note creation is refused while note composition is marked. Quit unregisters and removes the event handler. Carbon delivery through the application event target is assumed to occur on the main event loop; native SDK/dispatch/keyboard-layout/conflict behavior remains a Mac gate. No keyboard monitor, event tap, private API or Accessibility request is added. No blanket claim about native permissions is inferred from Linux tests.

`LoginService` uses public **`SMAppService.mainApp`**, not a LaunchAgent file, helper hack or legacy login-items API. On first native launch after schema7 migration, `unasked` prompts with **暂不启用** as the default button and **启用** as the explicit affirmative choice. Decline persists `declined`, never calls register, and subsequent launches do not ask again. Acceptance persists `requested` before attempting registration. OS failure remains visible and is never retried silently. Explicit Settings toggles can request register/unregister; current OS status is authoritative. Pending approval shows the switch on with an explanation so it can also be disabled. A button opens the public Login Items system settings page only on user action.

Persisted decisions are **consent history, not OS status**. Startup never re-registers a previously requested item. Imported consent never registers/unregisters anything; the existing machine's actual OS status remains visible. An imported `unasked` decision can ask on a later launch; imported `declined` remains declined. Registration denied/revoked/pending/not-found and throws are surfaced, not converted to a fabricated enabled state. Closing the consent question through its default/cancel response declines. A failed consent persistence write reports an error and cannot trigger registration.

Apple's [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice) provides `mainApp`; [register()](https://developer.apple.com/documentation/servicemanagement/smappservice/register()) describes login launch subject to approval; [requiresApproval](https://developer.apple.com/documentation/servicemanagement/smappservice/status-swift.enum/requiresapproval) distinguishes registered from eligible-to-run. These references establish API intent, not acceptance of this locally signed bundle. No Carbon/SMAppService code is compiled or invoked on Linux: the app/native tests remain inside the manifest's macOS conditional.

## Backup contract and atomic replacement

`Backup.swift` defines a **new native JSON format**, `format = local.desknodes.native.backup`, **format version 1**, **native schema 7**. It accepts only this version/schema combination. No Tauri compatibility, legacy discovery or automatic migration is assumed. `NativeBackup` is typed Codable, not arbitrary SQL, SQLite bytes or the internal placement-string format. Required collections must exist even when empty. Optional values use Codable's omitted/null semantics. Dates use Foundation Codable Date's numeric seconds since **2001-01-01 UTC**; civil keys remain validated Gregorian `YYYY-MM-DD` strings. IDs retain their typed UUID Codable representation. Future backup/schema evolution requires an explicit version decision.

| State | JSON coverage |
| --- | --- |
| Every retained note | ID, nil/empty title, eight-color palette, level, order, collapsed, automatic height, typed free/dock placement/display, saved free placement, created/updated/deleted timestamps |
| Every retained item | ID, parent, exact Unicode/combining/NUL/multiline text, completion, order, created/updated/deleted timestamps and optional `archivedDay` |
| Immutable history | Every day/capture timestamp, frozen note title/color/order/deletion and frozen item identity/text/completion/order/deletion/direct `carriedTo` |
| Native settings | Hour/minute, dock edge/display, automatic/manual edge preference |
| New preferences | Configured hotkey and unasked/declined/requested login decision |
| Scheduler and memberships | Optional active-day/high-water checkpoint; complete pending-deleted-note/item arrays; archives represented by each retained item's `archivedDay` |

Schema **6 → 7** transactionally adds singleton `native_preferences(id=1,payload)` with typed/default-validated hotkey and consent. All schema6 tables/columns/history triggers remain. Previous native migrations run in order. Existing migration fixtures now reconstruct the older schema by removing this new table and expect version7; assertions about preserved history/data were retained. In-memory text/deletion undo, transient all-topmost/promotion/drag state and actual OS registrations are not durable database state and are not serialized.

Export gates **all ordinary and reveal title/item marked composition before flushing**. It flushes only owning key-window editors through the existing N6/N7 method, inside the export transaction. Passive copies cannot publish stale text. Capture/rollover is not synthesized for a backup. Native `NSSavePanel` writes JSON atomically only after selection; cancel writes no backup file. Flush errors/false composition gate roll back repository writes.

Import checks composition before presenting `NSOpenPanel`, decodes/validates in isolation, then requires a separate explicit **替换全部数据** destructive alert (Cancel is first/default). No database reset occurs on malformed input, incompatible version or cancellation. Replacement checks composition again immediately before mutation; it refuses rather than forcing commit/cancel or queueing a later destructive operation. A conflicting imported shortcut refuses the entire import while keeping the old data/binding. Imported login intent has no OS effects.

Validation checks format/schema/types/enums, finite dates/geometry and positive sizes, nonnegative full-width order, free-only restore geometry, duplicate IDs/day/memberships, live parent references, snapshot parent/item ownership and uniqueness, valid civil days/carry rules, archive snapshot/completion/text/order consistency, tombstone pending memberships and checkpoint after sealed history. Native order positions may tie or have gaps; stable UUID tie-break remains authoritative. Archived rows cannot also be user tombstones. No normalization/clamping/re-ID/timestamp repair is applied to make invalid input pass.

A **true SQLite in-memory staging Store** runs the current ordered migrations, inserts all validated data inside a transaction, and enforces native CHECK/PK/FK constraints. Snapshot children precede sealing day headers with deferred FK checking, exactly as capture requires. Archives/memberships/checkpoint are then inserted, `foreign_key_check` and `integrity_check` must pass, and production readers/export validate the resulting database. Import never accepts schema SQL/triggers from JSON and never drops/disables history or archive integrity triggers.

Only that validated staging database can replace the destination through public **SQLite online backup API**. The Store lock excludes other shared-connection calls, active application transactions are rejected, and SQLite owns the destination write transaction until DONE. A failed/incomplete copy calls `sqlite3_backup_finish`, which rolls back the destination. It copies the complete validated schema **including sealing triggers** onto the same destination connection; no filesystem swap or period without integrity enforcement is used. This deliberately uses SQLite's own replacement transaction rather than nesting it in an incompatible application BEGIN. [SQLite's backup API](https://www.sqlite.org/c3ref/backup_finish.html) documents the write-transaction/unfinished-copy rollback behavior. Tests interrupt after a real first-page write, verify unchanged data after reopen, and retry successfully. No power-loss guarantee beyond SQLite's existing durability is fabricated.

After success, even identical imported IDs cause ordinary/reveal cards to invalidate before relinquishing responders. Their notification/save/flush and structural action paths become inert; local title/item/window undo is cleared. Reveal polling/delayed animation and docking controllers/closures/rails are retired; note windows are rebuilt from the shared Store. Shared deletion undo is discarded, transient all-topmost resets, visible History reloads, and reopening hidden History reloads too. Old UI cannot use native undo or delayed focus-loss flush to republish the replaced data. Ordinary refresh/rollover still retains surviving editors; invalidation is limited to removed cards/destructive import. Initial native layout may subsequently apply the pre-existing automatic-height fitting policy; no import-time topology repair rewrites the backup.
