## 1. 停靠条是什么

停靠就是把便签收进屏幕某条边上的“抽屉”。停在同一条边的便签会自动排成一列（左、右）或一行（顶部），这一列就叫**停靠条**。

| 特点 | 说明 |
|---|---|
| 自动排列 | 进入停靠条的便签自动对齐、等宽、按顺序排，不用手动摆位置 |
| 拖出 | 拖住便签顶部离开约 48pt，变回自由便签 |
| 溢出 | 一条边放不下时，多出的便签变成末端 96pt 区域里的小标签，点一下切换显示 |
| 尺寸 | 左右停靠宽 288pt（R8，原 240pt），高度随内容；顶部停靠宽 220pt、高 260pt（屏高不足 700pt 时为 200pt） |
| 进入方式 | 只能通过便签菜单显式停靠；自由便签拖到边缘不会自动停靠 |

适合把常看的清单（今天、本周）固定在屏幕边上，不和其他便签混在一起。

## R1 便签菜单整理

**问题**：层级组里有“置顶”，下面又有一个“置顶／取消置顶”快捷开关，两者作用相同（`NotePanel.swift:361`、`:375`）。四个停靠项平铺，“移出停靠条”对自由便签显示为灰色，菜单很长。

**改版后结构**：

```
● ● ● ● ● ● ●              颜色
─────────────
✓ 桌面层
  普通
  置顶
─────────────
  停靠               ▸     顶部 / 左侧 / 右侧（当前所在边打 ✓）
  取消停靠                 只在已停靠时出现
─────────────
  折叠／展开
  随内容调整高度
  添加事项
─────────────
  选择多张…                进入 R5 选择模式，并选中这张
  删除便签                 红色
```

**规则**：

- 删除下方重复的“置顶”快捷开关。层级组的 ✓ 已经表明状态。
- “停靠 ▸”停到便签当前所在的显示器。
- “取消停靠”回到停靠前保存的自由位置（现有 `freeRestore`）。

**涉及代码**：`NotePanel.swift` 的 `contextMenu()`。

**验收**：菜单中“置顶”只出现一次；自由便签不显示“取消停靠”；停靠子菜单的 ✓ 和实际所在边一致。

## R2 选中描边跟随便签颜色

**问题**：选中描边固定为灰绿色（`Theme.swift` 的 `selection`）。压在紫色、粉色便签上颜色冲突，看起来像出错。

**方案**：

- 描边颜色取便签自身颜色的深一档，宽度仍为 1.5pt。

| 颜色 | 浅色模式描边 | 深色模式描边 |
|---|---|---|
| 宣纸 | `B59E74` | `C4B08A` |
| 柠黄 | `C9A93A` | `D6BE5C` |
| 杏 | `D9905F` | `E0A47E` |
| 樱 | `CF7F90` | `DB98A6` |
| 薰衣草 | `9A82C9` | `B5A2DE` |
| 雾蓝 | `6F97C4` | `92B4DA` |
| 薄荷 | `6FA585` | `8FC4A3` |

- 应用不在前台时，描边不透明度降到 45%。

**涉及代码**：`DesignTokens.swift` 给 `NotePalette` 增加 `selectionLightHex`／`selectionDarkHex`；`Theme.swift`；`NotePanel.swift` 的 `colors()`，并监听应用激活状态。

**验收**：七种颜色分别选中，描边和背景同色系；切到其他应用后描边变淡，切回恢复；深色模式下可见。

## R3 新建便签默认高 240pt

**问题**：默认“随内容”，空便签只有标题、一行和“添加事项”，约 136pt，显得很挤。

**方案**：

- 新建便签默认高度 240pt，约能放 4 行事项。
- `NoteMetrics.newHeightChoices` 改为 `[0, 200, 240, 300, 400]`（0 表示随内容）。
- 已保存了其他选项的用户保持原选择；只有没设置过的用户使用新默认值。

**涉及代码**：`DesignTokens.swift`、`PresentationDefaults.swift`（`note.newHeight` 默认值）、`SettingsWindow.swift`。

**验收**：全新安装后新建便签高 240pt；设置可以选 240；之前选过“随内容”的用户不受影响。

## R4 整理改为瀑布流

**问题**：现在按行排列，每行顶边对齐，下一行从这一行最高那张的底部开始。只要有一张很高，同行矮便签下方都会留大块空白。

**方案**：

- 宽度统一 288pt（不变），高度保留各自原样（不变）。
- 列数 = ⌊(可用宽 + 18) ÷ (288 + 18)⌋，与现在相同。
- 按持久化顺序逐张放进**当前最矮的一列**；同样矮时取左边那列。
- 一列放不下时换页，规则不变；避让工具条、多屏和分页逻辑不变。

**涉及代码**：`Arrangement.swift` 的 `layout(_:in:width:gap:)`；`ArrangementTests` 增加瀑布流用例（高矮混排、分页边界、单列）。

**验收**：一张 7 行便签和三张 1 行便签整理后，矮便签依次堆在同一列或相邻列，没有成片空白；同样输入多次整理结果相同。

## R5 批量删除（选择模式）

**目标**：用鼠标或键盘一次删除多张，不弹确认，删错了可以一次撤销。

### 进入与退出

| 入口 | 说明 |
|---|---|
| ⌘ 按住便签拖动 | 进入并从按下处直接拉出选框，一个手势完成进入和框选 |
| ⌘ 单击便签 | 进入并选中这张 |
| 便签菜单“选择多张…” | 进入并选中这张 |
| 菜单栏“选择便签…” | 进入，不预选；没有便签时禁用 |

工具条不加“选择”按钮，保持五个按钮。便签菜单和菜单栏是两个看得见的入口，给不知道 ⌘ 操作的用户使用。

退出：点“完成”、按 Esc、切换到其他应用、全局收起、删除完成后。

### 为什么框选从便签上开始

便签下面的桌面空白属于访达，应用收不到那里的拖拽（访达会把它当成框选桌面图标）；文档规定不使用全局事件监听和辅助功能权限。所以：

- 模式外：拖拽必须从便签上按 ⌘ 开始。按下后的拖动事件一直发给这张便签的窗口，指针移到空白处也不会中断。
- 模式内：在便签下方铺一层透明覆盖窗口，接住空白处的拖拽，任意位置都能拖框。

### 模式内的表现

- 所有便签像“浮起”一样临时到最前面，被其他窗口挡住的也能看见、能选中。不改变各自的层级设置。
- 覆盖层整屏轻微变暗（约 10%），表示处于特殊模式。
- 每张便签左上角出现 22pt 空心圆，选中后变为实心蓝色并打勾，同时显示蓝色描边。
- 正文不可编辑；点在便签任何位置都只做勾选，不拖动、不放光标。
- 屏幕底部中央出现操作条：`已选择 N 张便签 │ 全选 │ 删除 │ 完成`。未选中时“删除”禁用，左侧文字改为“单击便签勾选，或在空白处拖框”。

### 鼠标

| 操作 | 结果 |
|---|---|
| 单击便签 | 切换这张的选中状态，不需要按 ⌘ |
| 任意处按住拖动（空白或便签上） | 出现半透明矩形选框，和选框重叠的便签实时选中；选框以外的取消 |
| 按住 ⌘ 拖框 | 在已有选择上追加 |
| 单击空白处 | 清空选择，留在模式里 |

### 键盘

| 按键 | 结果 |
|---|---|
| ⌘A | 全选当前可见的便签 |
| ⌫ 或 Delete | 删除选中的便签 |
| Esc | 退出模式 |
| ⌘Z | 撤销刚才的批量删除 |

### 删除与撤销

- 不弹确认，选中的便签 0.18 秒淡出，然后退出模式。
- 提示条显示“已删除 N 张便签 · 撤销”，保持 5 秒；点“撤销”或按 ⌘Z 一次恢复全部。
- “最近删除”里每张便签单独列出，可以分别恢复。

### 边界

- 输入法组词中不能进入选择模式。
- 全局收起时进入，先展开。整理后不在当前页的便签不可见，不能被选中，⌘A 也不包含它们。
- 停靠中、折叠中的便签都可以选中，也都可以被框选。
- 多显示器时每块屏幕各铺一层覆盖层；一次拖框只作用于起点所在的屏幕。
- 选择模式和“浮起”同时触发时，以选择模式为准；退出后恢复之前的状态。

### 涉及代码

| 位置 | 改动 |
|---|---|
| 新文件 `SelectionOverlay.swift` | 每屏一个透明覆盖窗口，画选框，计算与便签的重叠 |
| `NoteSurfaces.swift` | `selection: NoteID?` 扩展为一组选择加一个主选中；新增模式开关 |
| `NotePanel.swift` | 模式内拦截点击，只做勾选；显示勾选圆；模式外 ⌘ 按下即进入模式，后续拖动转为框选 |
| `NoteActions.swift` | 新增 `deleteNotes(_:)`，一个事务删完；撤销栈新增“一组便签”记录 |
| `DeletionToast.swift` | 文字显示张数；新增底部操作条 |
| `Application.swift` | 菜单栏新增“选择便签…” |

**验收**：⌘ 单击和 ⌘ 拖动都能进入模式；⌘ 拖动时指针移出便签不中断；框选、⌘ 追加、⌘A、⌫、Esc 各自生效；删除 3 张后一次撤销全部恢复且身份、内容、位置不变；“最近删除”出现 3 条；组词中无法进入。

## R6 文字大小

**位置**：设置新增“外观”分组 → “文字大小”，分段控件：小／标准／大／特大，下方实时预览一行示例事项。在便签中按 ⌘+ 放大一档、⌘− 缩小一档、⌘0 恢复标准，和设置同步。

| 档位 | 标题 | 事项 | 次要文字 | 比例 |
|---|---|---|---|---|
| 小 | 15 | 13 | 11 | 0.93 |
| 标准（现在） | 16 | 14 | 12 | 1.00 |
| 大 | 18 | 16 | 14 | 1.14 |
| 特大 | 20 | 18 | 15 | 1.29 |

**规则**：

- 对所有便签生效，不支持单张设置，避免整理和停靠时尺寸混乱。
- 行高、勾选框、标题区和底部“添加事项”区按同一比例缩放；便签宽度和内边距不变。
- “随内容调整高度”的便签自动重算高度，上限 480pt 不变；手动高度的便签保持高度，内容在内部滚动。
- 停靠便签的高度随之重算。
- 工具条、设置、历史窗口的文字不受影响。
- 保存在本机偏好（与工具条设置相同），不进入导出备份。

**涉及代码**：`DesignTokens.swift` 的 `NoteMetrics` 字号、行高等常量改为乘以比例（`Sources/DeskNodesApp` 中约 16 处引用）；`NoteTextView`、`NotePanel` 的 `preferredHeight`；`PresentationDefaults.swift`；`SettingsWindow.swift`；菜单快捷键。补充四个档位的高度计算测试。

**验收**：四档切换后，标题、事项、勾选框对齐无错位；随内容的便签高度随之变化；输入法组词中切换不丢字；重启后保持。

## R7 删除设置里的“停靠条”分组

**现状作用**：设置 → 停靠条 → 停靠位置／显示在，点击后把**所有已停靠的便签**整体搬到所选的边和显示器（`Docking.swift` 的 `dockPreference`）。

**问题**：

1. 没有便签停靠时，点了只保存一个值，看不到任何变化。
2. 它不是新便签停靠的默认边；单张菜单会直接停到你点的那条边。
3. 便签停在不同边时，点一下会全部归到同一边，原来的分布无法撤销。
4. 样式是“选一个状态”的分段控件，看起来像偏好，实际是一次性命令；高亮的值也不一定是便签实际所在的边。

**方案**：删除整个分组；`DockController.swift:335` 附近同样的“显示器 → 顶部／左侧／右侧”菜单一并删除。停靠只在单张便签菜单中操作（R1）。数据库 `dockEdge`／`displayID` 字段保留，保证旧备份能导入。

**涉及代码**：`SettingsWindow.swift`、`DockController.swift`；同步更新 `scripts/` 中引用该设置的检查脚本。

**验收**：设置里没有“停靠条”；旧备份导入成功；已停靠的便签位置不变。

## R8 侧边停靠宽度改为 288pt

**问题**：侧边停靠宽 240pt，自由便签 288pt，两者并排时宽窄明显不同。

**方案**：左右停靠宽度改为 288pt，与自由便签一致；顶部停靠保持 220pt，一排能多放几张。代价是侧边多占 48pt 屏幕宽度。

**涉及代码**：`Docking.swift` 的 `layout`；`DockController.swift` 中按 240 计算高度的两处；`DockingTests`。
